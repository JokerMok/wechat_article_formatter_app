# 非技术产品经理用 Codex 拆解鲲云算法包

## 素材类型

公众号案例草稿，状态为待事实核验、授权确认和脱敏审校。

## 核心信息

一个非算法工程师的产品经理，借助 Codex 阅读鲲云平台文档、检查本地依赖和运行工具，把“算法包做不出来”拆成模型转换、RBO、平台插件 SDK、运行时 ABI、设备验证和正式上传包等不同缺口。

文章的重点不是 Codex 替代算法工程师，而是产品经理可以把陌生技术资料先整理成可验证问题，再带着证据推进技术协作。

## 内容结构

1. 从产品经理身份和任务背景切入。
2. 区分单独 RBO 与可安装、可调度的完整平台算法包。
3. 通过本地动态库和依赖检查定位 `RBAlgSDK`、插件接口和设备验证缺口。
4. 记录 Codex 能完成的模型转换、RBO 生成、输入输出校验和暂存包结构。
5. 保留“中间产物不等于正式交付”的边界。

## 2026-08-20 延伸素材：训练数据与部署包分层

后续可补一段更具体的工作方法：旧算法输出的红框图不是人工真值，不能直接进入训练集。可靠的流程是“干净原图/视频 → 旧模型预标注 → 人工逐张复核 → 独立标注文件 → 数据集基线 → 训练与部署分层验收”。

这一段不使用客户细节，重点说明产品经理如何判断“模型预测、训练真值、部署包和现场运行”不是同一个交付对象。关联方法见 [[methodologies/detection-training-data-truth-boundary]]。
