# 四平台发布链路验收记录

## 版本范围

本次集成以现有工作树为准。原有修改保存于 `ed3207a`，验收分支 `c2da2b7` 的内容完整性保护在 `bd21e31` 合入。开发分支为 `codex/product-readiness`，不修改 `main` 的历史。

产品面向已经拥有源稿、需要编辑并输出多平台版本的作者。源稿是事实依据，平台工作稿是可编辑副本，平台成品是生成结果。默认仅排版不改写文案；传播力优化由用户开启，输出仍需作者审定。

## 架构与修复

`SourceDocument → ContentBlueprint → PlatformDesignPlan → 确定性渲染与导出` 是主链路。语法树保存内容和位置，语义分析负责论证关系，平台计划负责内容组织，渲染器负责字体度量、布局和分页。视觉主题与内容骨架分别选择。

服务端故障来自协议与执行边界，而非统一错误提示：模型提示缺少 Schema 枚举，还要求返回 Schema 不接受的字段；分析调用未传递推理强度，超时预算不足。现改为由同一 Zod Schema 生成输出协议、携带安全校验反馈进行有界重试，并以总请求预算控制上游请求。结果中的来源、数字、单位和引用必须通过校验。

分析结果在相同源文、模式和引擎下复用。仅排版在本地完成平台渲染；传播力优化逐个平台请求模型，不重复请求整篇语义分析。顶部和编辑区生成按钮使用同一工作稿入口。待生成稿纳入保存与恢复，异步返回不能覆盖期间发生的人工编辑。

公众号使用富文本章节层级，抖音长文使用连续阅读样式；小红书与抖音图文采用各自画布和字号约束。图文预览与 PNG 使用同一个 Canvas 渲染入口。图片保持比例，嵌套列表和引用中的图片进入图片节点；载入失败及文字溢出时阻止导出。

本机证据目录为 `artifacts/product-readiness/`，包含上线前页面截图、五类文章的四平台截图、逐页 PNG、HTML、`matrix.json`、四平台真实 AI 成品截图和 `live-ai-results.json`。该目录不纳入 Git，以免提交批量产物。真实模型浏览器验收脚本为 `tests/e2e/live-ai-acceptance.mjs`，需要支持原生 TypeScript 导入的 Node.js 22.18 或以上版本。

## 发布边界

- 生产构建必须配置独立的 `AI_ACCESS_CODE`，包括 Vercel Preview。不得把 `AI_API_KEY` 当作站点访问口令，也不得写入前端变量。
- 当前限流为实例内计数，不是多实例总额度或全站费用上限。对外开放需有共享限流或受控入口。
- 本机 Chromium 验证不等于微信公众号后台验收。富文本及图片在真实公众号后台的粘贴结果仍需账号环境确认。
- 本地语义分析是确定性基础结果，不具备模型级理解能力。数字和引用检查也不能替代完整事实核查，优化稿仍需作者复核。
- 本次没有修改生产配置或生产用户数据；代码推送与生产发布分开处理。
