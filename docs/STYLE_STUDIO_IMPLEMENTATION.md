# 风格排版工作台：本地实现与验收边界

日期：2026-11-05。需求基线：[PRD V1.0](./PRD_STYLE_STUDIO_V1.md)。原始 PRD 保留原文，不把目标指标改写成已通过。

## 入口与数据

- `/`：公众号风格排版工作台，包含稿件、风格学习、个人风格库、编辑和封面。
- `/multiplatform`：原有四平台工作区，保留原数据及原有 AI 分析、传播优化和图文导出能力。
- 新工作台使用独立 IndexedDB `wechat-style-studio-v1`，文章、最近 30 个修订、风格版本、图片、封面、封面风格分别保存。旧库未删除或迁移；已有稿件仍可从多平台入口打开，再通过 HTML / Markdown 导入新工作台。
- 两个工作区的数据保存在同一浏览器和网站源下；换端口、换域名或清空网站数据会影响本地数据可见性。交付包包含本篇 HTML、结构化稿件、风格、所用本地图片及已选封面；它不是两个工作区的完整备份。

## 运行与视觉模型

```bash
npm install
npx playwright install chromium
npm run dev
```

URL / HTML 采集需要 Node.js、Playwright Chromium 和浏览器运行依赖。生产实例必须提供这些条件；尚未验收 Serverless 浏览器打包。参考抓取是隔离的无登录会话，不使用本机已有浏览器的登录状态。

复用现有服务端 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 等配置；可另外设置 `AI_VISION_MODEL` 为支持图片输入的接入点 ID，未设置则使用 `AI_MODEL`。密钥不得使用 `NEXT_PUBLIC_` 前缀。访问口令及实例级限流规则沿用原项目。

2026-11-05 实际上游返回 `InvalidEndpoint.ClosedEndpoint`。此错误说明当前接入点关闭或暂不可用，不能据此断言模型不支持视觉输入。本次没有启用、替换接入点或修改密钥。用户已确认后续重新提供可用接入点。需启用一个有图片权限的接入点后，再执行真实截图与封面分析验证。

## 公众号 URL 采集修复

旧链路在三个公开样本上均未取得正文。用同一 Node HTTPS 传输对照，旧 User-Agent 触发 `302 /mp/wappoc_appmsgcaptcha`，更换为普通桌面浏览器请求头后取得正文。三个正文页面约 3.49 至 3.54 MB，均超过原 3 MB 上限。采集到的正文容器在源 HTML 中初始隐藏，隔离渲染需恢复其可见性。旧 HTML 清理规则也会移除内联样式和类名。

| 项目 | 源码中实际使用的路径 | 对当前实现的取舍 |
|---|---|---|
| wechat-download-api | 优先使用 `curl_cffi` 的 Chrome 请求配置，可经代理池或直连，回退到 httpx。正文接口处理 HTML、文本和图片，服务本身有管理员扫码鉴权。 [HTTP 客户端](https://github.com/jasonyy2018/wechat-download-api/blob/512aecd0e248a6385e51c883a0ca14d24b9874ca/utils/http_client.py) · [正文路由](https://github.com/jasonyy2018/wechat-download-api/blob/512aecd0e248a6385e51c883a0ca14d24b9874ca/routes/article.py) | 采用 HTML、正文文本和图片分别输出的结构。当前无登录 Node 路径已取得正文，未接入代理池或该服务。 |

三篇实际页面验收共加载 16/16 张正文图片。首轮「文旅之声」返回 `verification_required`，随后一次独立请求成功。另有一篇真实文字分享恢复 111 个正文字符。原文长图、套版及尝试明细在 [公众号采集验收](../artifacts/style-studio/wechat-capture/公众号采集验收.html)。本次改动覆盖 8 项定向单测、1 条既有 HTML 学习浏览器流程、TypeScript、改动范围 ESLint 及差异检查。

## 全文导入与直接编辑

空白稿自动聚焦到「粘贴整篇文章」，一次粘贴即显示正文。纯文本根据空行、缩进和断句识别段落，保留自然段内的硬换行。HTML 和 Word 导入保留语义结构，清理源样式后由当前主题排版。Word 在浏览器内转换，支持 .docx；旧版 .doc 需另存。已导入的图片可用剪贴板、拖放或文件选择补充。

真实 Chromium 验收覆盖 24 个自然段一次粘贴、多级标题与带图富文本、带表格和表内图片的 Word、Markdown 粘贴、Markdown/HTML/TXT 文件、图片粘贴与拖入、部分失败保留正文、直接编辑与块移动/删除、三套风格切换、撤销重做、刷新恢复及手机/桌面预览。原有局部样式、导出和响应式流程通过定向回归。[粘贴到切换风格的实录](../artifacts/style-studio/whole-article-import/whole-article-demo.mp4)

## 稿件管理、风格资产与排版规则

稿件删除写入回收站标记，保留正文、图片、封面和修订；列表支持单选、全选、确认批量删除和恢复。复制稿件为新 ID 并复制独立封面记录。现有 IndexedDB 表和索引沿用。自定义风格删除前显示引用篇数，保留引用方所需的精确版本与快照；内置风格禁止删除。三套增强内置风格为 v2，已应用 v1 的历史稿件仍可按 v1 加载。

原有采集只处理少量标题、引用和图片圆角。当前提取正文排版、页面宽度与留白、组件边框、标题层级、列表、分隔线、图片比例与位置、强调及章段间距，记录实际测到的类别。无法识别的语义组件使用主题降级样式。风格来源优先从保存的 HTML 重测；旧 URL 风格可重抓公开原文；仅有截图的旧风格依赖可用的视觉接入点。重新分析经确认后保存新版本。

缩略卡、画布与公众号内联 HTML 共享组件规则。全局参数、语义组件及用户局部覆盖按明确优先级合成；局部格式可逐块清除，也可一次清除后统一套版。正文仍保留语义强调、图文顺序和原始数据。独立读取导出文件已验证三套主题在 320、390、430 px 下的字号、行高、间距、图片和横向溢出，另验证富文本复制及交付包原图。真实公众号后台粘贴、转存和手机实机渲染尚待验收。

原工作台数据库的隔离副本中有两篇已有正文稿和一套已学习风格。本轮选取其中一篇真实稿件及该已学习风格进行交互验收。旧稿的单个容器重组为 152 个语义块，原有文本顺序保持。参考风格从原来的标题与图片补测到页面、正文与强调；同一稿件副本在三套主题下的桌面宽度为 660、540、720 px。样本原稿没有图，测试副本加入一张自制图检查保留与导出。截图、三种完整导出及测量记录见 [文章管理与套版验收](../artifacts/style-studio/management-and-layout/文章管理与套版验收.html)。

## 智能排版

全文导入会先渲染规则方案，再发起一次语义分析。已有稿件从编辑器打开「智能排版」即可开始。显式标题、章节、引用、表格、列表和图文关系沿用导入结构。分析仅发送可追溯的纯文本块和风格能力，不发送图片或 HTML。长文以章节为界分批，同时携带全文开头、结尾和纲要。只接受已存在的块引用、允许的角色和短理由。LayoutPlan 根据语义选择导语、重点、案例、数据、总结和分隔节奏，密度只约束强调总量。文章正文、图片及顺序始终从原数据渲染。

语义结构、方案及手动覆盖与稿件一起保存。快速换主题、恢复原布局、调整强调程度与局部修改均复用分析。修改过的单块按指纹跳过过时建议。只有新全文导入或主动重新设计会发起模型请求。风格捕获以 `editorial.measured` 标记明确实测的组件；没有测到的组件用当前主题的可解释默认样式。

排版模型默认使用本机 Ollama 和 `qwen3.5:4b`。可通过 `AI_LAYOUT_MODEL` 选择已安装模型，或显式设置 `AI_LAYOUT_PROVIDER=openai-compatible` 使用已配置的云端文本模型。设置为 `off`、调用失败、超时或校验失败时使用规则方案。现有截图分析配置独立。 [Ollama 结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)

真实稿件经本机模型分三批完成语义分析。保留 152 个原文块及八章，其中 139 块沿用原组件，五处采用导语、案例、观点或总结组件。模型标注五处，其中三处原文未加粗。三套主题切换、手动覆盖、刷新恢复、恢复原布局及 390 px 独立读取实际导出通过。原稿没有图片，另用带图用例核对图片引用和导出。 [源码核查、逐块决策和三套导出](../artifacts/style-studio/semantic-layout/真实稿件语义与排版验收.html)
