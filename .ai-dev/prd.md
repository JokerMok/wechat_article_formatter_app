## 1. 问题与目标用户

当前产品已具备公众号排版、富文本复制和图文卡片生成能力，但输入、公众号输出、轮播图输出、图片编辑和分页逻辑集中在单个大型组件中。不同输出共用原始文本，却没有统一的内容结构和独立的平台版本，导致功能互相牵连、编辑状态难以保存、平台扩展成本高。

目标用户是同时运营微信公众号、小红书和抖音的个人创作者。用户希望只维护一篇源文章，自动得到适合各平台的内容版本，在发布前完成文字、分页、图片和样式调整，再按平台导出。

## 2. 产品目标

1. 一篇源文章可生成微信公众号、小红书图文、抖音图文和抖音长文四种独立版本。
2. 保留源文章作为事实和观点基准，平台版本的人工修改不得反向污染源文章或其他平台版本。
3. 公众号输出可复制到微信编辑器；图文输出可生成无截断的高清图片组。
4. 项目、素材、平台版本和人工调整默认保存在当前浏览器本地。
5. AI 不可用时，基础结构识别、排版、编辑和导出仍可使用。

## 3. 可衡量结果

- 固定 12 篇代表性文章作为验收集，四种平台版本生成成功率为 100%。
- `3:4` 和 `9:16` 图文验收集中不出现文字、图片或页码越界；自动检查和人工截图复核均通过。
- 调整字号、行距、段距、画布比例或正文后，当前页及后续页在 500 毫秒内重新排版，不保留旧分页造成的空洞或截断。
- 刷新页面后，12 个验收项目的源文、素材、平台版本、分页和人工修改全部恢复。
- 公众号验收集复制到微信编辑器后，不出现裸露 Markdown、丢图或整体样式失效。
- AI 生成结果在验收集中不得新增源文无法支持的事实；标题、摘要、重点和平台文案均可逐项修改或恢复。
- `npm test`、`npm run lint`、`npm run build` 全部通过，现有 14 项测试不得删除或降低断言。

## 4. 范围

### P0：本轮开发

#### REQ-001 内容项目

用户可以新建、打开、重命名、自动保存和删除内容项目。每个项目包含源文章、文章信息、素材和四种平台版本。

验收标准：

- [ ] 新建项目后立即进入编辑工作区。
- [ ] 项目至少保存标题、源文、更新时间和平台生成状态。
- [ ] 删除项目需要二次确认，取消后数据不变。
- [ ] 无历史项目时显示可执行的空状态。

#### REQ-002 统一内容结构

系统把 Markdown 或普通文本转换为统一内容结构，识别标题、段落、引用、列表、图片、重点、分隔线和手动分页标记，并保留源文位置关系。

验收标准：

- [ ] 现有文章解析用例继续通过。
- [ ] 单独的 `>`、空标题、残留样式文本和无内容块不会进入结果。
- [ ] 输入中每段有效正文都能在统一内容结构中找到，不静默丢失。
- [ ] 解析失败时保留原文并降级为普通段落。

#### REQ-003 平台版本生成

用户可从同一源文章生成微信公众号、小红书图文、抖音图文和抖音长文版本。每个版本独立保存标题、正文、重点、标签、封面信息和生成状态。

验收标准：

- [ ] 四种版本可以分别生成和重新生成。
- [ ] 重新生成某个平台不改变其他平台和源文章。
- [ ] 已人工修改的版本重新生成前必须确认。
- [ ] 用户可以锁定版本或单页，锁定内容不会被重新生成覆盖。

#### REQ-004 AI 平台改写

AI 只负责平台标题、摘要、重点、发布文案、标签和图文分组建议，不负责最终渲染。输出必须通过固定结构校验，并提供无 AI 降级路径。

验收标准：

- [ ] 支持用户填写 OpenAI-compatible 服务地址、模型和密钥。
- [ ] 密钥默认只保存在当前会话；用户明确选择后才允许本地记住。
- [ ] AI 输出结构校验失败时不覆盖已有内容，并显示重试或使用基础版本。
- [ ] 请求失败、超时或限流时，确定性规则仍可生成可编辑版本。
- [ ] 用户可以查看本次生成对源文做了哪些删减或改写。

#### REQ-005 微信公众号版本

公众号版本保留完整文章结构，支持主题、字号、行距、段距、图片和直接编辑，并可复制带内联样式的富文本或导出 HTML。

验收标准：

- [ ] 当前主题和公众号样式继续可用。
- [ ] 预览正文可直接编辑，修改后复制和导出使用修改结果。
- [ ] 本地图片在项目内可显示，复制结果中包含图片节点。
- [ ] 复制到微信编辑器后不出现脚本、事件属性或外层应用样式。

#### REQ-006 小红书图文版本

小红书版本包含封面、`3:4` 图文页、标题、发布文案和标签。用户可编辑单页内容、分页、顺序和图片。

验收标准：

- [ ] 默认输出 `1080×1440` 图片。
- [ ] 首页具备标题和核心观点，正文页具备页标题或重点提示。
- [ ] 自动分页按实际画布容量执行，不按小节强制一节一页。
- [ ] 支持手动拆页、合页、排序、锁定和恢复自动分页。

#### REQ-007 抖音图文与长文版本

抖音图文支持 `3:4` 和 `9:16`，抖音长文包含标题、导语、正文、重点、结尾和发布文案。

验收标准：

- [ ] 图文比例切换后重新计算全部分页。
- [ ] 长文与图文版本分别保存，互不覆盖。
- [ ] 图文和长文均提供可复制的发布标题、正文和标签。
- [ ] 平台规则集中配置，不散落在页面组件中。

#### REQ-008 图文排版编辑

用户可调整字号、行距、段距、内容边距、标题大小和图片位置。调整后系统重新计算布局，优先压缩允许的样式范围，再增加新页，禁止截断内容。

验收标准：

- [ ] 修改任一排版参数后，当前页和后续页重新流式排版。
- [ ] 标题尽量与至少一段正文同页，避免孤立标题。
- [ ] 内容超过安全区域时自动续页，不通过裁切隐藏内容。
- [ ] 手动锁定的页面保持内容边界，其余页面重新排版。
- [ ] 支持撤销和重做最近 50 次平台版本修改。

#### REQ-009 素材管理

用户可以上传、粘贴和拖入图片，并在文章或图文页中插入、移动、缩放、裁剪、对齐和删除。

验收标准：

- [ ] 支持 PNG、JPEG、WebP，单文件上限 20 MB。
- [ ] 图片存入 IndexedDB，刷新后仍可使用。
- [ ] 不支持的文件、损坏文件和超限文件显示明确错误，不写入项目。
- [ ] 删除仍被内容引用的图片前显示引用位置和确认提示。

#### REQ-010 本地保存与恢复

项目状态、素材索引、平台版本和编辑历史默认保存在浏览器本地，并具备版本号和迁移入口。

验收标准：

- [ ] 输入和编辑停止 800 毫秒后自动保存。
- [ ] 存储失败时显示未保存状态，不误报成功。
- [ ] 新数据格式无法迁移时保留原始记录并允许导出备份。
- [ ] 清空浏览器数据前提供项目包导出能力。

#### REQ-011 分平台导出

系统根据当前平台提供对应导出方式：公众号富文本和 HTML；小红书、抖音图文 PNG/ZIP；抖音长文文本；完整项目备份包。

验收标准：

- [ ] 导出内容与当前预览及人工修改一致。
- [ ] 批量图片按平台、项目和页码稳定命名。
- [ ] ZIP 包包含图片、发布文案和清单文件。
- [ ] 剪贴板权限失败时提供下载或文本选择降级方式。

#### REQ-012 统一工作区

产品采用单一工作区：顶部管理项目和平台，左侧编辑源文章与素材，中间编辑当前平台版本，右侧显示真实尺寸预览和排版设置。

验收标准：

- [ ] 不再使用“公众号排版”和“轮播图生成”两个相互割裂的主入口。
- [ ] 切换平台不会丢失当前平台未导出的修改。
- [ ] 桌面宽度下三栏可同时使用；窄屏下按编辑、版本、预览三个视图切换。
- [ ] 所有主要操作均使用业务名称，不向用户显示内部数据结构术语。

#### REQ-013 错误处理与降级

解析、存储、AI、图片、剪贴板和导出错误均需显示具体原因和恢复动作，不得清空已有内容。

验收标准：

- [ ] 每类错误至少提供重试、降级或取消中的一种可执行动作。
- [ ] 未保存数据在错误发生后仍保留在当前会话。
- [ ] 同一错误不会无限自动重试。
- [ ] 错误日志不记录文章正文、图片内容或模型密钥。

#### REQ-014 质量与安全边界

所有生成结果必须可人工编辑和撤销。用户确认前不得自动发布、上传素材到项目服务器或执行不可逆操作。

验收标准：

- [ ] P0 不包含平台自动登录和自动发布。
- [ ] 除用户主动调用 AI 服务外，源文和素材不离开浏览器。
- [ ] AI 返回内容按纯数据处理，不允许注入脚本或事件属性。
- [ ] 全量测试、Lint 和生产构建通过后才允许集成。

## 5. 非目标

- 不做多人协作、账号体系、云端草稿同步和跨设备同步。
- 不做自动登录、自动发布、定时发布和账号运营数据分析。
- 不承诺平台内容一定获得流量，不使用阅读量作为排版质量指标。
- 不让 AI 自动添加案例、数字、引用或源文没有的事实。
- 不在 P0 引入 Tiptap 等完整富文本编辑器；源文继续使用 Markdown/普通文本，平台版本使用受控块编辑。
- 不直接复制个人非商业许可证或无明确许可证项目的代码。

## 6. 用户故事

- US-001：作为个人创作者，我输入一篇源文章后，可以一次生成四种平台版本，避免重复排版和复制。
- US-002：作为内容作者，我可以修改某个平台的标题、正文、重点和标签，同时保留源文章不变。
- US-003：作为图文发布者，我可以调整字号、间距和图片，系统自动重新分页且不截断内容。
- US-004：作为公众号作者，我可以直接编辑预览并把文字和图片复制到微信编辑器。
- US-005：作为本地工具用户，我刷新或关闭页面后可以继续上次项目，不丢失素材和修改。
- US-006：作为谨慎使用 AI 的作者，我可以检查改写差异、撤销结果，并在 AI 失败时继续工作。

## 7. 关键流程

1. 新建或打开项目。
2. 输入或导入源文章，系统识别文章结构。
3. 选择需要的平台并生成版本。
4. 在平台版本中修改标题、正文、重点、分页和图片。
5. 在真实尺寸预览中检查效果，调整排版参数。
6. 按平台复制或导出。
7. 系统自动保存项目，用户可导出完整备份。

## 8. 技术、数据与安全约束

- 继续使用 Next.js、React、TypeScript 和现有主题、公众号复制、Canvas 能力。
- 建立统一内容结构和独立平台转换层；页面组件不得直接实现平台规则。
- 解析、布局、分页、导出均使用确定性代码；AI 只生成受限的结构化内容建议。
- 使用 IndexedDB 保存图片和项目大数据，轻量偏好可使用本地存储。
- 平台规则使用带版本号的配置文件，便于平台限制变化后单独更新。
- AI 请求设置超时、次数上限和取消能力；密钥不得进入日志、仓库或导出包。
- 外部参考项目只借鉴交互和架构；代码使用必须先核验许可证。

## 9. AI 验收方式

- 建立 12 篇固定文章集，覆盖叙事、知识、商业案例、长文、列表、引用、图片和异常 Markdown。
- AI 输出必须通过结构校验；校验不通过不得进入项目状态。
- 每次改写记录源版本、目标平台、模型、时间和人工是否接受，不记录密钥。
- 人工复核四项：事实一致、结构完整、平台可用、无明显模板化语句。
- 任一结果新增无法从源文支持的事实，当前 AI 版本不得通过验收。

## 10. 发布阶段

- 阶段 A：统一内容结构、本地项目和基础工作区。
- 阶段 B：迁移公众号与图文排版能力，完成平台独立版本。
- 阶段 C：接入 AI 改写、分平台导出和错误降级。
- 阶段 D：完成固定验收集、视觉回归和旧入口清理。
